## Architecture Principles

1. Cold, heavy effort and emotional legibility are core architecture, not optional polish. Preserve approved formulas/timings.
2. One writer per state domain; queries return immutable snapshots; commands validate before mutation.
3. One game clock with ordered minute transactions; real input/action/presentation time remains distinct. Skips never discard survival minutes.
4. Reproducible, physically legible failures: one attempt, one outcome, one commit. Hidden morale is never the visible physical cause.
5. Explicit scene composition and small typed ports rather than a globally mutable bus. Required ADRs ratify recommendations before coding.

## System Layer Map

    Presentation  Camera | Emotional Feedback | Ambient & Foley Audio | HUD
          ^ snapshots/events       | presentation adapter commands only
    Feature       Mishaps | Gathering | Fire | Morale
          ^ owner commands/queries | queued owner events
    Core          Terrain | Map | Character | Thermal | Interaction | Body | Needs | Inventory
          ^ clock/input/config ports
    Foundation    InputRouter | GameClock | RunCoordinator / scene wiring / run RNG
    Platform      Godot 4.7.2 / Jolt / Forward+ / desktop OS

Platform contains no game system, epic or owner. RunCoordinator/RNG are implementation services, not added gameplay scope. Recommended run-scoped services are explicitly injected by the application root, rather than gameplay autoload state surviving restart. Alternatives (autoload Clock, global event bus, custom kinematic controller) belong in ADRs, not binding decisions made here.

Layers constrain implementation imports, not all data direction. Core Thermal receives Feature Fire source values through a registration port; Core Interaction invokes Feature resolver ports without importing their concrete classes. Camera supplies a read-only yaw port to Character. Character supplies movement snapshots back. Stable snapshots and composition wiring break cycles; no service constructs or discovers its peer in a global singleton.

## API Boundaries and Per-System Data Flow

Signatures are typed pseudocode. IDs are stable StringName-compatible values; positions are world-space Vector3 meters; temperatures °C, wind m/s, mass kg. Distinguish game minutes/hours from real seconds. Snapshots contain values/IDs, not mutable owner containers. Result carries success/refusal code and localized reason key. Event/attempt tokens carry run_id and sequence: duplicate commits and late prior-run events are ignored. No owner guesses missing item/profile/target data into a successful outcome.

### M1 — Input & Action Map

- **Owns:** context, per-action holds, real-time buffers, active device, validated binding data. **Consumes:** InputMap actions and UI/context requests. **Exposes:** movement/action snapshots, glyph device and disconnect signal.
- **API:** sample_actions(real_delta_s) -> InputSnapshot; set_context(context) -> void.
- **Guarantees:** sole raw-event reader; exactly one Gameplay/UI/Locked context; switching clears holds/buffers. Preserve 0.15 s buffer and all named GDD bindings. Detect device by event type, not ID zero. Reject conflicting remaps; active-pad disconnect pauses with keyboard recovery. Hold timings are real seconds.
- **Flow:** InputRouter -> Character/Interaction/Camera synchronous input snapshot; device_changed -> HUD signal. UI requests context through a port; no raw keys outside InputRouter.
- **Engine:** InputMap, Input.get_vector, InputEventKey/JoypadButton, Node signals; input.md, HIGH 4.7 device behavior. **ADR:** F1.

### M2 — Time & Day Cycle

- **Owns:** day/minute/phase/rate mode and fractional accumulator. **Consumes:** pause and normal/wait/sleep requests. **Exposes:** minute_tick, boundary signals and immutable clock snapshot.
- **API:** request_rate_mode(mode, reason) -> void; snapshot() -> ClockSnapshot.
- **Guarantees:** day 1 at 13:00 by default; one ordered tick/minute including skips; <=120 owed ticks/frame with debt carried. Normal beats skip; wait cannot override sleep. Validate T1–T5 data and day cap 60; no secondary gameplay clocks.
- **Flow:** Clock -> Coordinator ordered minute signal -> subscribers synchronous staged steps; subscribers request rate changes, never write clock fields.
- **Engine:** Node signals and SceneTree pause integration; Time.get_ticks_msec only for real-time diagnostics, not survival time. Engine-wide references, LOW API / MEDIUM scheduling integration. **ADR:** F1.

## Data Flow

### Initialization order

1. Validate immutable item/action/profile/time/map tables. Apply GDD-specific reject/default or warn/ignore handling, never invent values.
2. Create run_id/seed/RNG and Clock paused/Input Locked; load Map identities/zones/bounds and Terrain grid/collision, then fixed-kit Inventory.
3. Construct Character at safe drop, Thermal query ports, Body/Needs defaults, then Interaction/Mishaps/Gathering/Fire/Morale. Empty heat registry is valid. Inject ports before any cross-system query.
4. Attach Camera/Feedback/Audio/HUD, register interactables and subscriptions, publish initial complete snapshot; enable Gameplay/unpause last. Restart disconnects old run listeners and invalidates tokens before replacing subtree.

### Frame update path

    InputRouter --InputSnapshot [sync, real seconds]--> Character / ActionRunner / Camera
    Character --surface_at(p, grade) [sync]-----------> Terrain
    Character <--Body / Needs / Inventory modifiers [read-only snapshots]
    Character --move_and_slide [physics frame]-------> Jolt
    Character --footfall [signal]--------------------> Terrain / Mishaps / Audio
    ActionRunner --elapsed real duration------------> staged action transaction
    Models --immutable snapshots--------------------> Camera / Feedback / HUD / Audio
    Presentation -----------------------------------> rendering/audio output

Physics frames do not advance survival time. Body and Needs take highest applicable movement/work activity, not a sum. Character reads a stable published Camera yaw to avoid scene-order cycles. Cosmetic random variation must not consume the authoritative gameplay RNG stream.

### Minute transaction and event/signal path

Recommended dispatch to ratify in F1/C4/C5: advance one game minute; snapshot movement/work and pre-step modifiers; Thermal inputs → Fire burn/source update → Inventory drying → Body integration → Needs integration/wake → terminal arbitration → Morale event flush → presentation publication. Cross-reading Body/Needs use a documented pre-step snapshot except immediate wake/death requests handled by Coordinator. C5 must pin this exact integration boundary against both GDDs before implementation; no approved formula is retuned.

Never rely on Godot signal connection order for causality. Queue same-minute events with run/sequence identity. Morale applies losses/failures/successes/comforts in its mandatory order then rates/derived state once. Day resets, sunrise/nightfall and wake-delayed offers stay tied to actual minute boundaries. Normal alarms beat skips. Every owed minute completes before the next; 120/frame catch-up carries debt, never drops ticks.

Action transaction: validate tools/target/permissions → snapshot duration multipliers/start rate → play effort loop/track real time → revalidate completion → one Mishaps attempt if profile → enqueue visible cause before outcome presentation → owner resolver commits result exactly once → apply tool-use/damage in GDD order → queue outcome/loss events. Animation callbacks do not cause duplicate results. Reserve/validate referenced stacks without consuming early; eating cancellation consumes nothing. Completed tool use can break after result; tool loss before completion force-cancels.

Validate whole file before swapping runs; corrupt/unknown schema leaves current run unchanged. Rebuild derived values/sources without fabricated loss/spike events. Serialization format/migration policy remains later ADR work.

## Proposed Performance Budgets

These are **PROPOSED**, warn-only profiling starting points, not final approved budgets or measurements. Project.yaml has no performance values; legacy preferences supply 60 fps/16.6 ms but leave draws/memory unspecified. No configuration is changed. QQ-01 reserves hardware/resolution/acceptance policy and final numbers for owner approval.

| Key | PROPOSED value | Rationale / measurement |
|---|---|---|
| performance.target_framerate | 60 fps | Matches terrain GDD and legacy target; effortful motion must still respond immediately. Measure release exports on nominated minimum macOS/Windows desktop, not llvmpipe/headless VM. |
| performance.frame_budget_ms | 16.6 ms | Conservative rounding of 1000/60. Track CPU/GPU separately; proposed p95 <=16.6 ms during worst visibility/cold/fire effects, with hitch reporting separate. |
| performance.draw_call_limit | 500 visible draws/frame | Initial ceiling for one authored map, instanced vegetation/resources and batched snow marks, leaving character/fire/UI headroom. Include shadow/depth-pass accounting explicitly in measurement policy. |
| performance.memory_ceiling_mb | 2048 MB resident process memory | Initial desktop ceiling including textures/meshes/audio/grid/footprint history; leave OS/shared-GPU headroom. Measure peak after long trail growth and repeated trips, not startup only. |

Preserve tighter existing GDD limits: Terrain grid <=8 MB, surface_at <=0.02 ms/query; Time <=0.02 ms/tick and combined subscribers <=0.5 ms/tick at sleep rate; Camera <=0.05 ms/frame plus <=0.1 ms for <=12 occluders; Inventory pickup/drop <=0.1 ms and drying <=0.05 ms/tick for 50 stacks; Audio <=24 voices. Other source acceptance/performance limits remain normative in the baseline. A worst catch-up of 120 x 0.5 ms is 60 ms: F1 must measure hitch recovery, not infer frame compliance from average sleep cost. Optimize costs/presentation scheduling, never discard survival ticks.

Terrain/snow spike remains the next unresolved technical proof: full-run footprints, flat-face readability, displacement/trail representation, memory growth and query cost at approved Camera. Compare batched trail texture/displacement versus mark representation during C1 implementation validation; do not assume one lifetime node/decal per footfall is affordable. If persistence cannot fit the proposed ceiling, escalate a measured trade-off rather than deleting marks or changing scope. Rig follow-up is final clip quality/retargeting/IK, not basic import feasibility.
